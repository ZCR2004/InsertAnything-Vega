# 现场操作顺序：从标定到九任务

当前分支 `feat/roco-vega-rl-sequence`。以下命令在**连接机器人 SDK、相机和 CAN 的现场 Linux 电脑**执行，工作目录为 `InsertAnything-Vega` 仓库根目录。Windows 本地用于编辑、离线检查和假硬件测试。

顺序：**机器人/TCP核对 → 相机检查 → 板面坐标标定 → 抓取标定与测试 → 夹持状态下记录 A → 空爪路径测试 → 单任务 RL → 单任务全流程 → 九任务。** 可以先手动装夹完成 A 和 RL 测试，再接自动抓取；两条线可以分别调通。

## 0. 建立本机配置

```bash
python run_roco_vega.py --mode template --output configs/roco.local.json
cp third_party/steadyhand/configs/robots/vega.json configs/robot.local.json
```

复制后逐项核对 `robot.local.json` 的机器人名、SDK、URDF、右臂 `tip_r`、固定关节、关节范围及右爪驱动。特别是 `joint_presets.right_ready` 及其中的位置必须是本机验证过的测量；原文件中的相机修正、路点、电流不是默认可信的标定。先填公共配置 `tcp_floor_m`、`camera_clear_waypoints_xyzw`、`free_speed_scale`，其余未知字段可以暂时为空。

现场推理不需要 Isaac Lab。Python 环境须同时能导入本机 SDK/Pinocchio/腕相机；RL 阶段再需要 Torch 和 Hexagon-III 权重。依赖说明见 [README](README.md)。

## 1. 先确认 TCP，再检查相机

先核对实物夹爪轴与 `tip_r` 的 FK/方向是否一致。有疑问时用上游 A/B/C/D 工具做工具坐标检查：

```bash
python run_roco_calibration.py --tool tcp-record --config configs/roco.local.json --output configs/tool_measurements.local.json
python run_roco_calibration.py --tool tcp-analyze --config configs/roco.local.json --output configs/tool_analysis.local.json -- configs/tool_measurements.local.json
```

`tcp-record` 只订阅状态，机器人由现场已有示教方式移动；A/B/C/D 是**工具坐标分析的四个姿态**，不是后面的“成功插入 A”。分析结果不会自动改写 URDF；若工具轴/偏移不对，先修正并复测，再做板面和任务标定。

相机检查：

```bash
python run_roco_calibration.py --tool snapshot --config configs/roco.local.json --output roco_runs/camera_check_01 --rgb-only
```

这一步不创建 `Robot()`、不移动机械臂，保存 head/wrist RGB 的 `.npy` 及 `metadata.json`。检查画面非黑屏、右腕对应 `wrist_a`，头部图像的 `camera_info` 内参可读。

**不必一开始就重做棋盘格内参标定。** 当前实现读取现场相机内参，并沿用比赛 URDF/相机安装变换，随后用板面参考点修正定位。若换过相机安装、内参缺失或存在明显畸变/重投影问题，则先处理相机内外参；板面标定不能代替完整手眼标定。

## 2. 标定任务板与机器人 base 的对应关系

空爪、公共路点和本机 RIGHT_READY 已检查后执行：

```bash
python run_roco_calibration.py --tool board --config configs/roco.local.json --output configs/board.local.json --confirm-physical-motion --coarse-speed-scale 0.35 --jog-speed-scale 0.30 --max-jog-mm 10
```

这是**会运动**的步骤：头部拍板 → 使用你的 camera-clear 路点和本机 RIGHT_READY → 依次人工校正中心、右上、右下、左下，按提示填写实测 TCP 到板面的净空高度，生成坐标轴和表面平面。上游称“五点标定”，本版本实际记录上述四个参考位置并推导未访问的角点。用 Ctrl+C 终止，不依赖上游提示中“输入任意字符取消”的措辞。

包装入口读取 `configs/robot.local.json`，不会把私有配置写进 `third_party`。不采用上游自动搜索的 camera-clear 位置，改用已填路点；首次失败即停止。该工具仍保留上游的头部回零和标定期间的软件急停处理，须现场监督。

完成后：

- 将 `board.local.json` 的 `head_q_rad` 三维值填入主配置，后续拍板保持相同头部姿态。
- 填主配置 `calibration_identity` 的机器人/base/TCP、测量时间、文件 SHA256 和夹持约定。可用 `sha256sum configs/robot.local.json configs/board.local.json` 获取哈希。
- 填允许的板平移/旋转变化阈值；完成这些公共项后置 `base_calibrated=true`。暂时不要把总 `calibrated` 置真。
- 后续定位以**人工校正的板中心**为基准，叠加相对于这次标定原始图像的相机 XY 位移。板旋转、升降、机器人/工具标定变化后需要重做相关标定。

## 3. 先把一个物体的抓取调通

以 `usb_a` 为例，填写它的 `pick`：板坐标系下初始物体中心/匹配半径/尺寸范围、接近路点、hover 和抓取 Z、夹爪姿态、闭合电流/速度、夹持宽度范围。

腕相机两个像素不要混淆：`feature_uv` 是悬停画面里要跟踪的物体特征，`goal_uv` 是该物体正确对准夹爪时特征应出现的像素。**goal 不一定是图像正中心。** 在同一悬停高度、姿态和一致夹持方式下标定。执行时 SteadyHand 会小幅移动 X/Y，测局部像素雅可比，再闭环对齐；初始特征必须落在有效目标上，这不是任意散乱场景语义抓取。

先用 `verification.retention.mode="operator"`、`supervised=true`，完成后置该任务 `pick_calibrated=true`。不用填成功 A、不用权重、其他八项任务可继续为空。

```bash
python run_roco_test.py --test pick --task usb_a --config configs/roco.local.json --mode check
python run_roco_test.py --test pick --task usb_a --config configs/roco.local.json --mode live --confirm-empty-gripper --confirm-calibrated-paths
```

行为：识别 → 对齐 → 下降夹取 → 提起 → 验证持有。然后等待输入 `return`，在原抓取 XY 下放回原处、松爪、上抬，**不执行插入**。原位置必须仍可放回。取消/失败时停止，不自动松爪或退离。

## 4. 记录成功插入 A 和转运位置

每个物体分别按固定夹持深度/方向夹好，末端保持垂直向下，用现场已有示教方式完成一次成功插入；夹爪仍夹着物体时记录：

```bash
python record_roco_pose.py --robot-config configs/robot.local.json --label usb_a_success_A --output configs/usb_a_A.local.json
```

此脚本只读关节状态并计算 FK，**不会重连控制 Robot、不会夹爪 home 或发运动**。读取五次稳定样本，输出 `pose_xyzw`；复制到任务 `success_pose_xyzw`。它记录的是 TCP，不自动判断物体是否真正插好，正确夹持和插入状态由操作员确认。

用同一个脚本和不同 label/output 记录抓取悬停、camera-clear、转运、手动装夹、放置验证等位置。坐标统一为 base 下 m 和 `xyzw` 四元数。成功 A、物体相对夹爪姿态和板标定必须对应同一几何关系。

`entry_height_m=0.045` 自动生成 A 上方 4.5 cm，**不用单独标定这个中间点**。填写 `transfer_waypoints_xyzw`（路径保持在中间点高度以上）、速度，然后置该任务 `approach_calibrated=true`。每个物体分别填 A；电池也一样。

## 5. 空爪测试到 A 上方的路径

```bash
python run_roco_test.py --test plan --task usb_a --config configs/roco.local.json --mode check
python run_roco_test.py --test plan --task usb_a --config configs/roco.local.json --mode live --confirm-empty-gripper --confirm-calibrated-paths
```

重新拍板补偿 XY 平移后，逐路点显示目标，每次输入 `move` 才执行，并记录实测位置/姿态误差。最终停在 **A+4.5 cm**，不去 A、不下插、不运行 actor、不夹物体。结束不会自动倒着走回起点。这里的“规划”是已教路点 + IK + SDK 轨迹，不是带全局碰撞检测的运动规划器。

## 6. 独立测试单任务 RL，不依赖自动抓取

再补该任务的深度/XY/姿态容差、超深限值、超时、`policy_mapping`、权重路径及 SHA256、放置验证视角。Hexagon-III 的策略空间成功位姿与孔位姿需要匹配 checkpoint 定义，不能一律置零。新增 `manual_load_waypoints_xyzw` 是**空爪移动到便于手动装入物体的位置**，属于固定 base 路点。核对完成后置该任务 `calibrated=true`；公共 `base_calibrated=true` 即可，其他任务无须完成。

```bash
python run_roco_test.py --test insert --task usb_a --config configs/roco.local.json --mode check
python run_roco_test.py --test insert --task usb_a --config configs/roco.local.json --mode live --confirm-empty-gripper --confirm-calibrated-paths
```

行为：**空爪启动并 home 一次 → 拍板 → 到装夹位并打开 → 放入物体、移开手、输入 `grip` → 验证持有 → A 上方 4.5 cm → RL → 深度持续达标 → 松爪 → 退离 → 放置验证。** 全程同一会话；不要在启动这个脚本前就夹着物体。

这条入口跳过自动识别/抓取物体，但保留拍板和持有/放置检查。测试 `battery_size1` 或 `battery_size5` 时自动使用规划下插，不加载 RL 权重。

## 7. 合并单任务，再扩展到九任务

单个任务的自动抓取和独立插入分别稳定后：

```bash
python run_roco_vega.py --mode check --config configs/roco.local.json --task usb_a
python run_roco_vega.py --mode live --config configs/roco.local.json --task usb_a --confirm-empty-gripper --confirm-calibrated-paths
```

这是完整“识别→夹取→转运→插入→放置”，不会等待手动装夹。全部九项标定/单任务测试完成后，把总 `calibrated=true`，去掉 `--task usb_a` 才运行九任务序列。

## 离线测试与查看结果

```bash
python -m unittest -v test_roco_vega
python run_roco_test.py --test plan --task usb_a --mode simulate
python run_roco_test.py --test pick --task usb_a --mode simulate
python run_roco_test.py --test insert --task usb_a --mode simulate
```

不传 `--mode live` 不会连接控制硬件。`--mode check` 按所选阶段校验，只有用 RL 的阶段加载权重做前向；不是可达性/碰撞证明。模拟模式使用假硬件，不需要现场配置、Torch 或权重。

每次生成独立的 `roco_runs/<时间>/events.jsonl`。规划看 `plan_readback`；夹取看 `pick_test_lift_verified`；插入看 `insertion_sample`、`release_verified`、`task_completed`。独立测试成功记录 `stage_test_passed`。不要把“命令已发出”当成“动作成功”。

当前验证到假硬件和配置/失败路径；真实 checkpoint、相机图像、IK/SDK时序及零力插入成功率仍需现场执行上述阶段测试。

本次验证：44 项集成/配置/故障测试及 5 项原 backend 测试通过；plan、pick、RL insert 三个 CLI 假硬件入口均完成，电池 insert 入口确认 actor 调用为 0。标定包装器的配置转交和只读记录器通过离线测试，未连接现场硬件。
